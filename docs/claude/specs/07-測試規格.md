## 1. 測試策略概述

BiMAP Housekeeping 採用**多層次測試策略**，確保系統在各種場景下的穩定性與安全性。

### 1.1 測試金字塔

```
              ┌─────────────────┐
              │  E2E 測試       │  手動/自動（測試環境驗證）
              │  End-to-End     │
              └─────────────────┘
                     ▲
                     │
              ┌─────────────────┐
              │  集成測試        │  自動化（CI/CD）
              │  Integration    │
              └─────────────────┘
                     ▲
                     │
              ┌─────────────────┐
              │  單元測試        │  ✅ 自動化（go test）
              │  Unit Tests     │  55 個測試案例
              └─────────────────┘
```

### 1.2 測試層級

| 層級       | 覆蓋範圍    | 測試工具                | 執行頻率  | 當前狀態             |

#### 2.4.2 Filter 組合盤點

以下盤點以 **filter engine + validation 規則** 為準，表格中的「合法性」表示該組 filter 是否會被目前程式接受。

- `delete_indices` 並不是唯一有額外安全限制的 action/filter；`space`、`water_level`、`node_role` 也都要求整組 filters 中必須包含至少一個 `pattern`。
- 此處所稱「必須包含 `pattern`」是指 **整組 filters 內至少要有一個 `pattern` filter**，不是額外再加第二個 `pattern`。因此像 `age + pattern`、`pattern + space`、`node_role + pattern` 都屬於合法組合。

| Filter 組合 | 合法性 | 目前狀態 | 測試覆蓋 |
| ---------- | ---- | ------- | ------- |
| `age` | ✅ 合法 | 已實作 | ✅ 已覆蓋 |

註記：

- `age` + `node_role`、`space` + `node_role`、`water_level` + `node_role` 雖然執行期有防呆或殘留分支，但依現行規格一律視為非法配置，因為 `node_role` 必須搭配 `pattern`。
- `pattern` 單獨路徑已覆蓋 `prefix`、`suffix`、`regex` 與多值並列。
- 目前 action/filter 盤點範圍內的主要合法與非法組合已補齊，自動測試缺口主要剩在 action 執行流程與真實 ES 互動。

## 3. 測試環境

### 3.1 開發環境測試

**要求**:

- Go 1.23.4 或更高版本
- Elasticsearch 7.x 或 8.x（可選，用於集成測試）

**執行命令**:

```bash
# 所有單元測試

# 特定模組測試

# Race Detector（強制重跑，不吃 cache）
GOCACHE=/tmp/go-build go test -race -count=1 ./...

# 查看覆蓋率
go test ./... -cover

# 詳細覆蓋率報告
go test ./... -coverprofile=coverage.out
go tool cover -html=coverage.out
```

### 3.2 測試環境驗證（E2E）

**詳細計劃**: 參考 [測試環境驗證計劃_3.3.md](../測試環境驗證計劃_3.3.md)

#### 3.2.1 環境需求

```yaml
Elasticsearch:
  版本: 7.x 或 8.x
  節點數: 至少 1 個
  狀態: Green 或 Yellow
  可用磁碟空間: > 10 GB

測試數據:
  系統 Index: .kibana, .security, ilm-history-*, etc.
  測試 Index: logs-test-*, metrics-test-*, etc.
```

#### 3.2.2 測試場景

**Layer 4 驗證**（配置驗證）:

- [ ] delete_indices 無 pattern → Fail Fast
- [ ] space 無 pattern → Fail Fast
- [ ] water_level 無 pattern → Fail Fast
- [ ] age + space → Fail Fast
- [ ] age + water_level → Fail Fast
- [ ] space + water_level → Fail Fast

**Layer 1 驗證**（Pattern Filter）:

- [ ] `.kibana` 被自動排除
- [ ] `.security` 被自動排除
- [ ] `ilm-history-*` 被自動排除
- [ ] 正常 index 正確匹配

**Layer 2 驗證**（Filter Combination）:

- [ ] pattern + space 正常工作
- [ ] pattern + water_level 正常工作
- [ ] 單獨 space 被拒絕
- [ ] 單獨 water_level 被拒絕

**Layer 3 驗證**（Delete Action Protection）:

- [ ] 嘗試刪除系統 index → 操作中止
- [ ] 刪除正常 index → 操作成功
- [ ] 日誌記錄完整

**End-to-End 測試**:

- [ ] Test Mode 預覽正確
- [ ] 實際執行符合預期
- [ ] Metrics 記錄完整
- [ ] 日誌回寫 ES 成功
