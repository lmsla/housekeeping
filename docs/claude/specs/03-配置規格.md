## 1. 配置文件概述

BiMAP Housekeeping 使用 **雙配置文件系統**：

| 文件              | 用途          | 範例                              |
| --------------- | ----------- | ------------------------------- |
| **setting.yml** | 環境與服務設定     | `configs/setting.yml.sample` |
| **config.yml**  | Action 動作定義 | `configs/config.yml.sample`  |

**配置載入位置**: 與執行檔同目錄

---

## 2. setting.yml - 環境配置

### 2.1 完整範例

```yaml
# Elasticsearch 連接配置
url: "https://localhost:9200"
username: "elastic"
password: "changeme"

# 執行模式
execute_cron: false    # true: Cron模式, false: 單次執行
period: "0 2 * * *"    # Cron表達式（僅 execute_cron=true 時生效）
test_mode: false       # true: Dry-run（僅預覽）, false: 實際執行

# 日誌配置
log:
  path: "/var/log/bimap-housekeeping/"
  rotate_days: 7
  toes: true           # 日誌回寫 ES
  health_check_interval: 60  # Cluster Health 監控間隔（秒）
```

### 2.2 參數詳解

#### ES 連接參數

- **url**: ES 集群地址（支援 HTTPS）
- **username** / **password**: ES 認證資訊

#### 執行模式參數

- **execute_cron**: 
  
  - `false`: 執行一次後退出
  - `true`: 常駐服務，按 Cron 排程執行

- **period**: Cron 表達式（標準 5 欄位格式）
  
  - 範例: `"0 2 * * *"` = 每天凌晨 2:00
  - 範例: `"*/30 * * * *"` = 每 30 分鐘

- **test_mode**:
  
  - `true`: **Test Mode** (Dry-run) - 僅預覽，不實際執行
  - `false`: 實際執行 Actions

## 3. config.yml - Action 配置

### 3.1 配置結構

```yaml
actions:
  - action: <action_type>         # 必填: 動作類型
    description: <description>    # 選填: 說明
    disable_action: false         # 選填: 是否停用此 action
    delay: 10                     # 選填: 執行後延遲（秒）
    options:                      # action 特定選項
      <key>: <value>
    filters:                      # 必填: Filter 列表
      - filtertype: <type>
        <filter_params>
```

---

## 4. Actions 類型

### 4.1 delete_indices

**功能**: 刪除匹配的索引

**範例**:

```yaml
- action: delete_indices
  description: "刪除 30 天前的日誌索引"
  filters:
    - filtertype: pattern
      kind: prefix
      value: logs-
    - filtertype: age
      direction: older
      unit: days
      unit_count: 30
```

**安全要求**:

- ✅ **必須** 配置 `pattern` filter（P1 強制檢查）
- ❌ 禁止無 pattern 的配置

---

### 4.2 allocation

**功能**: 索引分層遷移（Hot/Warm/Cold）

**範例**:

```yaml
- action: allocation
  description: "將 1 天前的索引移至 Warm 層"
  options:
    key: "_tier_preference"
    value: "data_warm"
    allocation_type: "include"
  filters:
    - filtertype: pattern
      kind: prefix
      value: logs-
    - filtertype: age
      direction: older
      unit: days
      unit_count: 1
```

**Options 參數**:

- **key**: `_tier_preference` (推薦) 或自定義屬性
- **value**: `data_hot`, `data_warm`, `data_cold`
- **allocation_type**: `include`, `exclude`, `require`

---

### 4.3 forcemerge

**功能**: 減少 segment 數量，優化查詢性能

**範例**:

```yaml
- action: forcemerge
  description: "Force merge 歸檔索引"
  options:
    max_num_segment: 1
  filters:
    - filtertype: pattern
      kind: prefix
      value: archive-
```

---

### 4.4 close / open

**功能**: 關閉/開啟索引

**範例**:

```yaml
- action: close
  description: "關閉歸檔索引"
  filters:
    - filtertype: pattern
      kind: prefix
      value: archive-
```

---

### 4.5 rollover

**功能**: 別名式索引輪轉

**範例**:

```yaml
- action: rollover
  description: "日誌索引 Rollover"
  options:
    rollover_alias: "logs-write"
    max_size: "50gb"
    max_age: "7d"
    max_docs: 100000000
```

**重要**:

- Rollover **不使用 filters**（直接操作 alias）
- 需預先配置 alias 與 write index
- 參考: [docs/ROLLOVER_GUIDE.md](../../docs/ROLLOVER_GUIDE.md)

## 5. Filters 類型

### 5.1 pattern

**功能**: 名稱匹配

**參數**:

- **kind**: `prefix`, `suffix`, `regex`
- **value**: 匹配值（支援陣列）

**範例**:

```yaml
# Prefix 匹配
- filtertype: pattern
  kind: prefix
  value: logs-

# 多個 prefix
- filtertype: pattern
  kind: prefix
  value:
    - logs-
    - metrics-

# Regex 匹配
- filtertype: pattern
  kind: regex
  value: "^logs-\\d{4}\\.\\d{2}\\.\\d{2}$"
```

**安全機制**:

- 自動排除系統 index (`.kibana`, `.security`, etc.)
- 日誌記錄排除的系統 index

---

### 5.2 age

**功能**: 時間篩選

**參數**:

- **direction**: `older`, `younger`
- **unit**: `seconds`, `minutes`, `hours`, `days`, `weeks`, `months`
- **unit_count**: 數量

**範例**:

```yaml
# 超過 30 天
- filtertype: age
  direction: older
  unit: days
  unit_count: 30

# 7 天內創建
- filtertype: age
  direction: younger
  unit: days
  unit_count: 7
```

---

### 5.3 space

**功能**: 保留最新 N GB，刪除更舊的索引

**參數**:

- **disk_space**: 保留容量 (GB)

**範例**:

```yaml
- filtertype: pattern
  kind: prefix
  value: logs-
- filtertype: space
  disk_space: 100  # 保留最新 100GB
```

**安全要求**:

- ✅ **必須** 配合 `pattern` filter（P1 強制檢查）
- ❌ 禁止單獨使用

---

### 5.4 water_level

**功能**: 磁碟使用率超過閾值時刪除最舊索引

**參數**:

- **upper_limit**: 磁碟使用率上限（%）

**範例**:

```yaml
- filtertype: pattern
  kind: prefix
  value: logs-
- filtertype: water_level
  upper_limit: 80  # 磁碟使用率 >80% 時觸發
```

**安全要求**:

- ✅ **必須** 配合 `pattern` filter（P1 強制檢查）
- ❌ 禁止單獨使用

---

### 5.5 node_role

**功能**: 依節點角色篩選索引（Hot/Warm/Cold）

**參數**:

- **value**: 角色值（可單值或陣列）
  - `h` = data_hot
  - `w` = data_warm
  - `c` = data_cold

**範例**:

```yaml
- filtertype: node_role
  value: h
```

```yaml
- filtertype: node_role
  value:
    - h
    - w
```

**注意事項**:

- node_role 需搭配其他 filter（`age` / `pattern` / `space` / `water_level`）使用
- 含 `space` / `water_level` 時，仍必須配合 `pattern` filter

## 6. Filter 組合規則

### 6.1 支援的組合 ✅

| 組合                        | 說明      | 範例用途                        |
| ------------------------- | ------- | --------------------------- |
| `age` alone               | 僅時間過濾   | 刪除所有 30 天前的索引（需謹慎）          |
| `pattern` alone           | 僅名稱過濾   | 刪除特定前綴的所有索引                 |
| `age` + `pattern`         | 時間 + 名稱 | **最常用**：刪除 logs- 開頭且超過 30 天 |
| `pattern` + `space`       | 名稱 + 容量 | 保留 logs- 最新 100GB           |
| `pattern` + `water_level` | 名稱 + 水位 | 磁碟 >80% 時刪除 logs- 最舊索引      |
| `age` + `node_role`       | 角色 + 時間 | Warm 節點上超過 30 天的索引         |
| `node_role` + `pattern`   | 角色 + 名稱 | Hot 節點上 logs- 前綴索引         |
| `age` + `node_role` + `pattern` | 角色 + 時間 + 名稱 | Warm 節點上 logs- 且超過 30 天 |
| `node_role` + `pattern` + `space` | 角色 + 名稱 + 容量 | Warm 節點保留 logs- 最新 100GB |
| `node_role` + `pattern` + `water_level` | 角色 + 名稱 + 水位 | Warm 節點磁碟 >80% 時刪除 |

### 6.2 禁止的組合 ❌

| 組合                      | 原因   | 錯誤訊息                                        |
| ----------------------- | ---- | ------------------------------------------- |
| `age` + `space`         | 邏輯衝突 | "age 和 space 過濾器不能同時使用"                     |
| `age` + `water_level`   | 邏輯衝突 | "age 和 water_level 過濾器不能同時使用"               |
| `space` + `water_level` | 邏輯衝突 | "space 和 water_level 過濾器不能同時使用"             |
| `space` alone           | 極度危險 | "space filter 必須配合 pattern filter 使用"       |
| `water_level` alone     | 極度危險 | "water_level filter 必須配合 pattern filter 使用" |
| `node_role` + `space`（無 pattern） | 極度危險 | "space filter 必須配合 pattern filter 使用" |
| `node_role` + `water_level`（無 pattern） | 極度危險 | "water_level filter 必須配合 pattern filter 使用" |

**違反規則結果**:

- **啟動時**: Fail Fast → `os.Exit(1)`
- **錯誤訊息**: 清楚說明違反的規則

## 7. 完整配置範例

### 7.1 典型生產配置

```yaml
# config.yml
actions:
  # 1. 刪除 30 天前的日誌
  - action: delete_indices
    description: "刪除舊日誌索引"
    filters:
      - filtertype: pattern
        kind: prefix
        value: logs-
      - filtertype: age
        direction: older
        unit: days
        unit_count: 30
    delay: 5

  # 2. 移動 1 天前的索引到 Warm 層
  - action: allocation
    description: "Hot → Warm"
    options:
      key: "_tier_preference"
      value: "data_warm"
      allocation_type: "include"
    filters:
      - filtertype: pattern
        kind: prefix
        value: logs-
      - filtertype: age
        direction: older
        unit: days
        unit_count: 1
    delay: 5

  # 3. 移動 7 天前的索引到 Cold 層
  - action: allocation
    description: "Warm → Cold"
    options:
      key: "_tier_preference"
      value: "data_cold"
      allocation_type: "include"
    filters:
      - filtertype: pattern
        kind: prefix
        value: logs-
      - filtertype: age
        direction: older
        unit: days
        unit_count: 7
    delay: 5

  # 4. Force Merge Cold 層索引
  - action: forcemerge
    description: "優化 Cold 層"
    options:
      max_num_segment: 1
    filters:
      - filtertype: pattern
        kind: prefix
        value: logs-
      - filtertype: age
        direction: older
        unit: days
        unit_count: 7
```

## 8. 配置驗證

### 8.1 驗證工具

**手動驗證**:

```bash
# Test Mode 驗證配置
./bimap-housekeeping  # 確保 test_mode: true
```

**檢查點**:

- ✅ 配置語法正確（YAML）
- ✅ 通過 Fail Fast 驗證
- ✅ Test Mode 日誌顯示預期匹配的索引
- ✅ 無系統 index 被選中

### 8.2 常見錯誤

**錯誤 1**: delete_indices 無 pattern

```yaml
❌ 錯誤配置:
- action: delete_indices
  filters:
    - filtertype: age
      direction: older
      unit: days
      unit_count: 30

✅ 正確配置:
- action: delete_indices
  filters:
    - filtertype: pattern
      kind: prefix
      value: logs-
    - filtertype: age
      direction: older
      unit: days
      unit_count: 30
```

**錯誤 2**: space 無 pattern

```yaml
❌ 錯誤配置:
- action: delete_indices
  filters:
    - filtertype: space
      disk_space: 100

✅ 正確配置:
- action: delete_indices
  filters:
    - filtertype: pattern
      kind: prefix
      value: logs-
    - filtertype: space
      disk_space: 100
```
