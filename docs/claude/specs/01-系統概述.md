## 1. 專案簡介

### 1.1 專案目標

BiMAP Housekeeping 是一個專為 Elasticsearch 集群設計的索引生命週期管理服務。其核心目標是：

1. **自動化索引管理** - 減少人工介入，降低運維成本
2. **安全可靠** - 防止誤刪除系統索引，確保集群穩定性
3. **靈活配置** - 支援多種 Filter 組合，滿足不同業務需求
4. **可觀測性** - 完整的監控與日誌，即時掌握集群狀態

### 1.2 為什麼需要這個系統？

**痛點**：

- Elasticsearch 集群隨著時間累積大量過期索引
- 手動管理索引耗時且容易出錯
- 缺乏統一的索引生命週期管理機制
- 磁碟空間告警頻繁，需要緊急處理

**解決方案**：

- 基於時間、磁碟容量、水位線自動刪除/遷移索引
- Hot→Warm→Cold 分層自動化
- Test Mode 預覽，避免誤操作
- 完整的監控與告警機制

## 2. 核心功能

### 2.1 索引生命週期管理

| 功能                 | 說明            | 典型用例                               |
| ------------------ | ------------- | ---------------------------------- |
| **Delete Indices** | 刪除匹配的索引       | 清理 30 天前的日誌索引                      |
| **Allocation**     | 索引分層遷移        | Hot (SSD) → Warm (HDD) → Cold (歸檔) |
| **Force Merge**    | 減少 segment 數量 | 優化查詢性能                             |
| **Close**          | 關閉索引          | 歸檔很少訪問的數據                          |
| **Open**           | 重新開啟索引        | 恢復訪問                               |
| **Rollover**       | 別名式索引輪轉       | 時間序列數據管理                           |

### 2.2 安全防護機制

**四層防禦架構** (2025-11-26 P0/P1 修復完成):

```
Layer 4: Startup Configuration Validation (Fail Fast)
         ↓
Layer 3: Action Execution Protection (handleDeleteIndices)
         ↓
Layer 2: Filter Combination Validation (tools.go)
         ↓
Layer 1: Filter Level Protection (filters.go)
```

**系統 Index 保護**:

- 自動排除 `.kibana`, `.security`, `.monitoring-*` 等系統索引
- 強制要求 `delete_indices` 配置 `pattern` filter
- `space`/`water_level` filter 必須配合 `pattern` 使用

### 2.3 靈活過濾器

**支援的 Filter 類型**:

| Filter          | 功能                        | 範例             |
| --------------- | ------------------------- | -------------- |
| **pattern**     | 名稱匹配（prefix/suffix/regex） | `logs-*`       |
| **age**         | 時間篩選（older/younger）       | 超過 30 天        |
| **space**       | 保留最新 N GB                 | 保留最新 100GB     |
| **water_level** | 磁碟水位線觸發                   | 磁碟使用率 >80% 時刪除 |
| **node_role**   | 節點角色（hot/warm/cold）       | 限制索引所在節點角色  |

**支援的組合**:

- ✅ `age` alone
- ✅ `pattern` alone
- ✅ `age` + `pattern`
- ✅ `pattern` + `space`
- ✅ `pattern` + `water_level`
- ✅ `node_role` + `pattern`
- ✅ `age` + `node_role` + `pattern`
- ✅ `node_role` + `pattern` + (`space` / `water_level`)

**禁止的組合** (會觸發 Fail Fast):

- ❌ `age` + `space`
- ❌ `age` + `water_level`
- ❌ `space` + `water_level`
- ❌ `node_role` 單獨使用（無 pattern）
- ❌ `age` + `node_role`（無 pattern）
- ❌ `space` / `water_level` 單獨使用（無 pattern）

### 2.4 Test Mode (Dry-Run)

**功能**:

- 預覽將要執行的操作，不實際修改索引
- 日誌中明確標註 "Test mode"
- 顯示匹配的索引列表

**使用場景**:

- 驗證配置正確性
- 評估影響範圍
- 生產部署前測試

## 3. 系統特性

### 3.1 關鍵特性

| 特性             | 說明                             |
| -------------- | ------------------------------ |
| **分散式部署**      | 支援 RPM/DEB 打包，標準化部署            |
| **服務化運行**      | Systemd Service 或單次執行          |
| **Cron 排程**    | 定時自動執行，無需外部 cron               |
| **日誌回寫**       | 日誌寫回 ES，方便 Kibana 可視化          |
| **Metrics 監控** | 本地 Metrics + Cluster Health 監控 |
| **Shard 告警**   | Shard 數量接近限制時自動告警              |

### 3.2 系統邊界

**包含**:

- ✅ ES 索引生命週期管理
- ✅ 集群健康監控
- ✅ Shard 限制監控
- ✅ 配置驗證與安全檢查

**不包含**:

- ❌ ES 集群部署與配置
- ❌ Kibana 管理
- ❌ 數據備份/恢復（建議使用 Snapshot）
- ❌ Index Template 管理

```

│                                                          │

│  │  Config      │───>│ Main Process │  │   Metrics   │ │
│  │  Validation  │    │  (Cron/Once) │  │  Collection │ │
│  └──────────────┘    └──────┬───────┘  └──────┬──────┘ │
│                              │                 │         │
│                      ┌───────▼────────┐       │         │

│                      │  (Actions Loop) │       │         │

│                              │                 │         │
│            ┌─────────────────┼─────────────┐  │         │
│            │                 │             │  │         │
│       ┌────▼────┐    ┌──────▼──────┐  ┌──▼──▼─────┐   │
│       │ Filters │    │   Actions   │  │  Logger   │   │
│       │ Process │    │  Executor   │  │  (3 types)│   │
│       └────┬────┘    └──────┬──────┘  └─────┬─────┘   │
│            │                 │                │         │
└────────────┼─────────────────┼────────────────┼─────────┘
             │                 │                │
             └─────────┬───────┘                │
                       │                        │
                    ┌──▼────────────────────────▼─┐
                    │   Elasticsearch Cluster     │
                    │  (indices, metrics, logs)   │
                    └─────────────────────────────┘
```

### 5.2 數據流向

1. **配置載入**: 讀取 `setting.yml` 和 `config.yml`
2. **配置驗證**: Fail Fast 檢查（Layer 4）
3. **ES 連接**: 建立 ES Client
4. **Cluster Health 監控**: 背景 Goroutine 持續監控
5. **Action 執行循環**:
   - 讀取 Action 配置
   - 應用 Filters 獲取匹配索引（Layer 1-2）
   - 執行 Action（Layer 3）
   - 記錄 Metrics 與日誌
6. **日誌回寫**: 寫入 ES 指定索引
7. **Metrics 輸出**: 打印摘要或持續更新

## 7. 部署模式

### 7.1 單次執行模式

```bash
# 手動執行一次
./bimap-housekeeping
```

**使用場景**:

- 測試配置
- 緊急手動清理
- Dry-run 驗證

**配置**:

```yaml
execute_cron: false
test_mode: false  # 或 true (dry-run)
```

### 7.2 服務模式 (Cron)

```bash
# Systemd Service
systemctl start bimap-housekeeping
```

**使用場景**:

- 生產環境自動化
- 定時索引清理
- 持續監控

**配置**:

```yaml
execute_cron: true
period: "0 2 * * *"  # 每天凌晨 2 點
```

## 9. 系統限制

### 9.1 已知限制

| 限制項目            | 說明               | 影響            | 解決方案              |
| --------------- | ---------------- | ------------- | ----------------- |
| **單一 ES 集群**    | 僅支援連接一個 ES 集群    | 無法同時管理多集群     | 部署多個實例            |
| **順序執行**        | Actions 順序執行，無並行 | 大量 Action 時較慢 | 調整 delay 參數       |
| **Rollover 限制** | 需預先配置 alias      | 首次使用需手動設置     | 參考 ROLLOVER_GUIDE |
| **Cron 精度**     | 分鐘級別，無秒級         | 無法精確到秒        | 符合多數場景需求          |

### 9.2 容量規劃

**建議規格** (單一實例):

- **索引數量**: <10,000 個
- **Actions 數量**: <50 個
- **CPU**: 1 Core
- **記憶體**: 256MB
- **磁碟**: 100MB (日誌輪轉)

**擴展方案**:

- 索引數量過多：分批處理，使用更嚴格的 pattern filter
- Actions 過多：拆分為多個配置文件，分時段執行
- 高可用性：部署多實例（主備模式）
