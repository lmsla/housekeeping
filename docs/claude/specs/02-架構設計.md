## 2. 核心組件設計

### 2.1 Configuration Layer

**職責**: 載入、解析、驗證配置文件

**主要模組**:
- `utils/config_loader.go`: 載入 YAML 配置
- `utils/validation.go`: **四層防禦 Layer 4** - 配置驗證（Fail Fast）

**關鍵流程**:
1. 載入 `setting.yml` (環境配置)
2. 載入 `config.yml` (Action 定義)
3. 驗證配置合法性
4. 不合法 → `os.Exit(1)` (立即終止)
5. 合法 → 繼續執行

**安全檢查**:
- ✅ delete_indices 必須有 pattern filter
- ✅ space/water_level 必須配合 pattern
- ✅ 禁止互斥 filter 組合

---

### 2.2 Filter Processing Layer

**職責**: 根據 Filter 配置篩選索引

**主要模組**:
- `job/filters.go`: **四層防禦 Layer 1** - Filter 級別保護
- `job/tools.go`: **四層防禦 Layer 2** - Filter 組合驗證

**Filter 類型實現**:

| Filter | 函數 | 安全機制 |
|--------|------|---------|
| pattern | `FilterType_pattern()` | 自動排除系統 index |
| age | `FilterType_age()` | 時間篩選 |
| space | `FilterType_space()` | 要求 pattern，否則返回空 |
| water_level | `FilterType_waterLevel()` | 要求 pattern，否則返回空 |

**Filter 組合邏輯** (`ResolveCompareListNonRole`):
```go
支援的組合:
- age alone → agelist
- pattern alone → patternlist
- age + pattern → Indicesmapping2(agelist, patternlist)
- pattern + space → Indicesmapping2(patternlist, spacelist)
- pattern + water_level → Indicesmapping2(patternlist, water_level_list)

拒絕的組合:
- space alone → 返回空列表 + ERROR 日誌
- water_level alone → 返回空列表 + ERROR 日誌
- 其他未定義組合 → 返回空列表
```

---

### 2.3 Action Execution Layer

**職責**: 執行索引操作

**主要模組**:
- `job/actions.go`: **四層防禦 Layer 3** - Action 執行保護
- `job/indices.go`: ES API 操作實現

**核心流程** (`Action_controll`):
```
For each Action in config.yml:
  1. 產生 UUID (execution ID)
  2. 處理 Filters → 獲取匹配索引列表
  3. 根據 Action 類型執行:
     - delete_indices → handleDeleteIndices() (含最終防線檢查)
     - allocation → handleAllocation()
     - forcemerge → handleForceMerge()
     - close/open → handleClose/Open()
     - rollover → handleRollover()
  4. 記錄 Metrics
  5. 應用 delay (如有配置)
```

**Action Executor 模式**:
```go
type ActionExecutor struct {
    UUID   string
    Action string
}

func (e *ActionExecutor) ExecuteOnIndices(
    indices []string, 
    operation func(string) error,
) {
    if TestMode {
        logTestMode(indices)
        return
    }
    
    for _, idx := range indices {
        if err := operation(idx); err != nil {
            // 記錄失敗 metrics
        } else {
            // 記錄成功 metrics
        }
    }
}
```

## 3. 四層防禦架構 (Security Architecture)

**設計理念**: Defense in Depth - 多層防護，確保系統 index 安全

### 3.1 Layer 4: Startup Configuration Validation

**位置**: `utils/validation.go` + `main.go:65-69`
**觸發時機**: 程式啟動時（第一時間）
**機制**: Fail Fast

**檢查項目**:
```go
// 1. delete_indices 必須有 pattern
if action == "delete_indices" && !hasPattern {
    return error → os.Exit(1)
}

// 2. space/water_level 必須配合 pattern
if (hasSpace || hasWaterLevel) && !hasPattern {
    return error → os.Exit(1)
}

// 3. 禁止互斥組合
if hasAge && hasSpace { return error }
if hasAge && hasWaterLevel { return error }
if hasSpace && hasWaterLevel { return error }
```

**優點**: 配置錯誤立即發現，避免運行時意外

---

### 3.2 Layer 3: Action Execution Protection

**位置**: `job/actions.go:343-390` (`handleDeleteIndices`)
**觸發時機**: 刪除操作執行前（最終防線）

**實現邏輯**:
```go
func handleDeleteIndices(uuid string, comparelist []string, ...) {
    systemIndices := []string{}
    safeIndices := []string{}
    
    // 🔒 最終檢查：分離系統 index 和安全 index
    for _, idx := range comparelist {
        if isSystemIndex(idx) {
            systemIndices = append(systemIndices, idx)
        } else {
            safeIndices = append(safeIndices, idx)
        }
    }
    
    // 發現系統 index → 中止操作
    if len(systemIndices) > 0 {
        global.Logger.Errorw("🚨 CRITICAL: Attempting to delete SYSTEM indices - OPERATION ABORTED", ...)
        return  // 不執行任何刪除
    }
    
    // 僅刪除安全 index
    executor.ExecuteOnIndices(safeIndices, DeleteIndex)
}
```

### 3.4 Layer 1: Filter Level Protection

**位置**: `job/filters.go` (各 FilterType 函數)
**觸發時機**: 每個 Filter 執行時

**Pattern Filter** (`FilterType_pattern:151-245`):
```go
for _, indexName := range allIndices {
```

### 3.5 系統 Index 黑名單

**位置**: `job/system_index.go`

**實現**:
```go
var systemIndexPrefixes = []string{
    ".",                  // .kibana, .security, .monitoring-*, .tasks, etc.
    "ilm-history-",       // ILM 歷史記錄
    "kibana_sample_",     // Kibana 範例數據
    ".ds-",               // Data streams 系統 index
}

func isSystemIndex(indexName string) bool {
    for _, prefix := range systemIndexPrefixes {
        if strings.HasPrefix(indexName, prefix) {
            return true
        }
    }
    return false
}
```

## 4. 數據流程

### 4.1 Action 執行流程（詳細）

```
[1] main.go 啟動
     │
     ├─> 載入 setting.yml, config.yml
     │
     ├─> ✅ ValidateConfig() [Layer 4]
     │    ├─ delete_indices 必須有 pattern?
     │    ├─ space/water_level 配合 pattern?
     │    └─ 無互斥組合?
     │    
     │    ❌ 不通過 → os.Exit(1)
     │    ✅ 通過 → 繼續
     │
     ├─> 初始化 ES Client
     │
     ├─> 啟動 Cluster Health Monitor (背景 Goroutine)
     │
     └─> [2] Action_controll() 循環

[2] Action_controll() - 處理每個 Action
     │
     ├─> 產生 UUID
     │
     ├─> [3] Process Filters
     │
     ├─> [4] Execute Action
     │
     ├─> 記錄 Metrics & Logs
     │
     └─> Apply delay → 下一個 Action

[3] Process Filters
     │
     ├─> FilterType_pattern() [Layer 1]
     │    └─> 自動排除系統 index (.kibana, .security, ...)
     │
     ├─> FilterType_age()
     │
     ├─> FilterType_space() [Layer 1]
     │    └─> 無 pattern → 返回空 + ERROR
     │
     ├─> FilterType_waterLevel() [Layer 1]
     │    └─> 無 pattern → 返回空 + ERROR
     │
     └─> [Layer 2] ResolveCompareListNonRole()
          └─> 組合驗證 (age+pattern, pattern+space, ...)

[4] Execute Action
     │
     ├─> delete_indices → handleDeleteIndices() [Layer 3]
     │    │
     │    ├─> 🔒 最終檢查：分離系統 index
     │    ├─> 發現系統 index → 中止操作
     │    └─> 僅刪除安全 index
     │
     ├─> allocation → handleAllocation()
     │
     ├─> forcemerge → handleForceMerge()
     │
     ├─> close/open → handleClose/Open()
     │
     └─> rollover → handleRollover()
```

## 5. 並發設計

### 5.1 Goroutine 使用

**Cluster Health Monitor** (獨立 Goroutine):
```go
// main.go:58
go cat_cluster.CatClusterHealth(es_client)
```

**特性**:
- 每 `health_check_interval` 秒收集一次
- 寫入 ES index: `housekeeping_cluster_health-YYYYMM`
- 監控 Shard 限制（warning: 800, critical: 950）
- 獨立運行，不影響主流程

**同步機制**:
- 無共享狀態（各自操作不同 ES Client）
- 日誌使用 zap（thread-safe）
- Metrics 使用 atomic operations

### 6.2 Retry with Backoff

```go
// indices.go:74 - ClusterHealthWithRetry
maxRetries := 3
backoff := time.Second

for i := 0; i < maxRetries; i++ {
    health, err := es_client.ClusterHealth().Do(ctx)
    if err == nil {
        return health, nil
    }
    
    time.Sleep(backoff)
    backoff *= 2  // Exponential backoff
```

## 7. 性能優化

### 7.1 批次處理

**Action 執行**: 順序執行（避免同時大量操作衝擊 ES）
**Index 操作**: 單一索引逐一處理（可控性高）

### 7.2 資源控制

- **Delay 參數**: 每個 Action 後可配置延遲
- **Filter 提前過濾**: 在 Filter 階段就盡量縮小範圍
- **Test Mode**: 預覽模式不實際操作 ES

---

## 8. 技術決策記錄

| 決策 | 原因 | 權衡 |
|------|------|------|
| **順序執行 Actions** | 避免同時大量操作，降低 ES 壓力 | 犧牲速度換取穩定性 |
| **四層防禦架構** | 多層保護，即使某層失效仍有後備 | 增加代碼複雜度，但安全性大幅提升 |
| **Fail Fast 驗證** | 配置錯誤立即發現，避免運行時意外 | 需要仔細測試配置 |
| **系統 Index 黑名單** | Prefix 匹配簡單高效 | 可能需要根據環境調整黑名單 |
| **Test Mode 分支** | 預覽功能對安全性至關重要 | 兩套邏輯需要保持一致 |
