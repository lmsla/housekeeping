## 1. ES 索引結構

BiMAP Housekeeping 本身操作 ES 索引，同時也將日誌與監控數據寫回 ES。

---

## 2. 日誌索引

### 2.1 索引命名

```
housekeeping-YYYYMM
```

**範例**:
- `housekeeping-202511`
- `housekeeping-202512`

### 2.2 文檔結構

```json
{
  "@timestamp": "2025-11-28T10:00:00Z",
  "logType": "Procedures",
  "level": "info",
  "message": "✅ 配置驗證通過",
  "uuid": "abc-123",
  "action": "delete_indices",
  "matched_indices": 15,
  "execution_time_ms": 1234
}
```

**logType 類型**:
- `Procedures`: 流程日誌（Action 執行流程）
- `Detail`: 詳細日誌（每個 index 操作）
- `Metrics`: 性能指標

### 3.1 索引命名

```
housekeeping_cluster_health-YYYYMM
```

### 3.2 文檔結構

```json
{
  "@timestamp": "2025-11-28T10:00:00Z",
```

## 4. Shard 監控

### 4.1 告警級別

| 使用率 | 狀態 | 日誌級別 | 說明 |
|-------|------|---------|------|
| < 80% | NORMAL | - | 正常範圍 |
| 80% - < 95% | WARNING | ⚠️ Warning | 接近上限，建議優化 |
| ≥ 95% | CRITICAL | 🚨 Error | 危險狀態，立即處理 |

**ES 預設限制**: `cluster.max_shards_per_node = 1000`（動態可配置）

**重要說明**：
- `max_shards_per_node` 設定值是 **動態讀取**，非硬編碼
- 程式啟動時自動從 ES 集群查詢 `cluster.max_shards_per_node` 設定
- 若查詢失敗則使用預設值 1000
- 告警閾值基於 **百分比**，自動適應不同的集群配置

### 4.2 計算邏輯

```go
// 從 global.MaxShardsPerNode 讀取動態值（啟動時初始化）
maxShardsPerNode := global.MaxShardsPerNode
shardUsagePercent := float64(shardCount) / float64(maxShardsPerNode) * 100
shardRemaining := maxShardsPerNode - shardCount

// 基於百分比判斷告警級別
if shardUsagePercent >= 95.0 {
    shardAlertLevel = "critical"
    log.Errorw("� Node shard usage CRITICAL", ...)
} else if shardUsagePercent >= 80.0 {
    shardAlertLevel = "warning"
    log.Warnw("⚠️  Node shard usage WARNING", ...)
} else {
    shardAlertLevel = "normal"
}
```

### 4.3 初始化流程

程式在啟動時執行以下步驟（`main.go` 第 96 行）：

```go
// 查詢並初始化 cluster.max_shards_per_node 設定值
if err := job.InitMaxShardsPerNode(ctx); err != nil {
    global.Logger.Warn("Failed to initialize max_shards_per_node, using default: 1000")
}
```

**優先級順序**（取第一個找到的值）：
1. Transient settings（最高優先級）
2. Persistent settings
3. Defaults（預設設定）

若三者都未找到，使用硬編碼預設值 1000。

## 5. Metrics 系統

### 5.1 本地 Metrics

**位置**: `metrics/metrics.go`

**收集項目**:
```go
type Metrics struct {
    // Operation counts
    TotalOperations int
    SuccessOperations int
    FailureOperations int
    
    // Action breakdown
    DeleteCount int
    AllocationCount int
    ForceMergeCount int
    CloseCount int
    OpenCount int
    RolloverCount int
    
    // Performance
    AverageExecutionTime time.Duration
    
    // ES Health
    ESConnected bool
    ClusterStatus string
    ResponseTime time.Duration
    
    // Resource usage
    MemoryUsage uint64
    HeapUsage uint64
    GoroutineCount int
}
```

### 5.2 輸出方式

**單次執行模式**:
```go
// main.go:96 - printMetricsSummary
fmt.Println("=== Metrics Summary ===")
fmt.Printf("Total Operations: %d\n", metrics.TotalOperations)
fmt.Printf("Success: %d, Failure: %d\n", metrics.SuccessOperations, metrics.FailureOperations)
...
```

**Cron 模式**:
- 每 30 秒更新一次資源使用指標
- 日誌級別: `Metrics`
- 可透過 log.toes 寫回 ES

## 6. 日誌策略

### 6.1 三種 Logger

| Logger | 用途 | 輸出 |
|--------|------|------|
| `global.Logger` | 一般流程日誌 | 本地檔案 + ES (可選) |
| `global.Detail_Logger` | 詳細操作日誌 | 本地檔案 + ES (可選) |
| `global.Stderr_logger` | 啟動錯誤 | Stderr (不寫 ES) |

### 6.2 日誌輪轉

**配置** (`setting.yml`):
```yaml
log:
  path: "/var/log/bimap-housekeeping/"
  rotate_days: 7
```

**檔案命名**:
```
housekeeping_YYYYMMDD.log
housekeeping_detail_YYYYMMDD.log
```

**自動清理**: 保留最近 7 天

---

## 7. ES 寫回配置

### 7.1 啟用日誌回寫

**setting.yml**:
```yaml
log:
  toes: true
  health_check_interval: 60
```

### 7.2 索引權限需求

- `indices:admin/create` - 建立日誌索引
- `indices:data/write/bulk` - 批次寫入日誌

---

## 8. 數據保留策略

### 8.1 日誌保留

| 類型 | 保留期 | 清理方式 |
|------|--------|---------|
| 本地日誌檔案 | 7 天 | 自動輪轉 |
| ES 日誌索引 | 依配置 | 可用 BiMAP Housekeeping 自身清理 |
| Cluster Health 索引 | 依配置 | 可用 BiMAP Housekeeping 自身清理 |

### 8.2 自我管理範例

```yaml
# config.yml - 使用自身清理日誌
- action: delete_indices
  description: "清理 90 天前的 Housekeeping 日誌"
  filters:
    - filtertype: pattern
      kind: prefix
      value: 
        - "housekeeping-"
        - "housekeeping_cluster_health-"
    - filtertype: age
      direction: older
      unit: days
      unit_count: 90
```
